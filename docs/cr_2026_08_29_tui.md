## P1 fixed

### P1-1  `service.py` recorder crashed on the turn-timeout error path

At [service.py:380](src/littrace/codex_runtime/service.py#L380), the
`except AppServerError` branch accessed `exc.error_code.value`
directly. Round 18 E2E surfaced a transient typed-error subclass
that did not populate `error_code` through its `super().__init__`
call, so the recorder crashed before the `system_error` row was
written and the turn failed without an audit trail.

**Fix**: defensively `getattr` the `error_code` and
`additional_details` with sensible defaults (`CodexErrorCode.OTHER`
and `{}`). `AppServerError.__init__` always sets both, so this is
a belt-and-braces guard for any future subclass that forgets to
call `super().__init__`.

```python
code = getattr(exc, "error_code", CodexErrorCode.OTHER)
recorder.append(
    type_="system_error",
    error_code=code.value,
    message=str(exc),
    additional_details=getattr(exc, "additional_details", {}) or {},
)
```

## P2 fixed (from Round 18 backlog)

### P2-1  Approval modal could not scroll long argument payloads

A `enqueue_download` request carrying 50 paper IDs overflowed the
modal and was silently truncated to `box_width - 4` rows. The
operator had no way to review the full payload before pressing
Y/N/Esc.

**Fix**: [`src/littrace/tui.py`](src/littrace/tui.py)

1. `ApprovalRequest` now carries pre-rendered `content_lines`
   (one item per row, JSON-serialised then split on `\n`).
   Computed once inside `_make_elicitation_handler` so the draw
   loop's cost stays flat regardless of payload size.

2. `_draw_approval_modal` reads `content_lines`, re-wraps each
   row to the box width, and renders a windowed slice via
   `approval.scroll_offset`.

3. `_handle_approval_key` gains Up/Down/PgUp/PgDn/Home/End
   (and `j`/`k`/`g`/`G`) scroll keys. The scroll clamps
   `scroll_offset` against `state.last_modal_body_rows` (refreshed
   on every draw) so the modal never pages past its visible window.

4. Scroll keys do **not** resolve the future; the modal stays
   open until Y/N/Esc.

### P2-2  Elicitations arriving during an active approval were dropped

If a second `mcpServer/elicitation/request` arrived while the
operator was still reviewing the first one, the handler
unconditionally set `state.pending_approval = approval` and the
earlier request's modal was silently stolen by the new one.

**Fix**:

1. `TUIState.approval_queue: list[ApprovalRequest]` — a FIFO of
   further elicitations that arrived while one was active.
2. `_make_elicitation_handler` parks the new approval in the
   queue when `state.pending_approval is not None`; the handler's
   `finally` only clears `pending_approval` if it owned that slot
   (queued ones keep their place in the queue).
3. `_advance_approval_queue(state)` pops the queue head onto
   `pending_approval`. Called from `_handle_approval_key` after
   every Y/N/Esc.
4. The handler test verifies the queue semantics: a second
   handler call while the first is still pending parks in the
   queue; the operator's Y resolves the first AND promotes the
   second onto the modal.

## P3 fixed (from Round 18 backlog)

### P3-1  `?` keystroke now renders an in-TUI help overlay

A full-page man-style overlay listing chat keys, approval keys,
scroll keys, slash commands, the `LITTRACE_TUI_TICK_MS` knob, and
the Ctrl-C abort hint. Rendered as a centered curses box on top of
the chat / context panes (which stay visible underneath). Any
non-`?` keystroke while the overlay is up dismisses it.

### P3-2  Configurable redraw cadence via `LITTRACE_TUI_TICK_MS`

`run_tui` reads the env var at startup, clamps it to
`[10, 1000]` ms (so a typo doesn't freeze the loop or burn CPU),
and writes it onto `state.tick_seconds`. The event loop's
`asyncio.sleep(state.tick_seconds)` replaces the hardcoded
`asyncio.sleep(0.05)`. Default is 50 ms when the env var is
unset or malformed.

## Lessons (added to the running list)

12. **Modal UIs must scroll**. A centered curses box with a
    fixed height is a regression waiting to happen. The first
    long-argument tool call will overflow; the operator will
    silently approve something they never saw. Pre-render the
    content into lines and clamp a scroll offset against the
    visible window on every draw.

13. **Concurrent async requests need a queue, not last-writer-wins**.
    The TUI's `state.pending_approval` was a single slot — fine
    for one elicitation, dangerous for two arriving close
    together. The same shape will show up anywhere an async
    transport can emit events mid-handler. Queue behind the
    current item; promote on resolve.

14. **Env-var knobs beat CLI flags for TUI helpers**. A
    `LITTRACE_TUI_TICK_MS=200` is one shell line; a `--tick-ms`
    flag requires the operator to know the flag exists. The
    help overlay documents the env var so discoverability is
    not worse than a flag.

## What's deliberately NOT done

- The real curses TUI subprocess launch is still not exercised
  in CI — Windows venv has no pexpect/wexpect/windows-curses.
  Same handler code path is covered by `scripts/_tui_handler_e2e.py`.
- The `content` field of the elicitation response is still
  always `{}` (no free-form operator input). LitTrace MCP
  tools are fire-and-forget so this is correct; a future
  `confirm_destructive_action` tool would need a text input
  row in the modal.
- `set_elicitation_handler` remains non-thread-safe on the
  shared `AppServerClient` (consistent with the rest of the
  client contract).
