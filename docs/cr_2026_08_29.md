## P1 fixes shipped in this commit

### P1-1  `_get_gateway` called `log.warning` on a name that does not exist

Three call sites in [src/littrace/mcp_server.py](src/littrace/mcp_server.py)
(lines 92, 97, 201 at the time of the review) used `log.warning(...)`
but only `logger = get_logger("mcp_server")` was bound at module load
time. Any MCP startup that hit the lazy plugin-discovery branch and
received a warning from `list_plugins()` (or whose marketplace scan
itself raised) would propagate `NameError: name 'log' is not defined`
out of `_get_gateway()`. The exception was not caught — every
subsequent tool call in the same process would re-raise the same
`NameError` because the `_GATEWAY` attribute was never bound to a
real gateway.

The two plugin-load blocks were marked `pragma: no cover - defensive`,
which is why CI never caught it. The new test
[`test_get_gateway_uses_logger_when_plugin_warning`](tests/unit/test_mcp_token_persistence.py)
re-runs the lazy path with a stub `list_plugins()` that emits a
warning, and asserts that `logger.warning` (not `log.warning`) is the
sink.

**Fix**: replace the three `log.warning` calls with `logger.warning`.
Rationale: keep a single logger name; adding `log = logger` would
just create a new symbol for the next person to typo.

### P1-2  MCP token file is written with default umask (world-readable)

`_get_or_create_mcp_token()` in the same module writes
`~/.codex/littrace-mcp.token` (or `$CODEX_HOME/littrace-mcp.token`)
without `os.chmod`. The file is a long-lived shared secret between
the parent LitTrace process and the spawned codex subprocess; the
same string is mirrored into the subprocess's `LITTRACE_MCP_TOKEN`
env var in `codex_runtime/service.py::_mcp_server_config` so it
authenticates every MCP call. On a typical umask-022 system the file
is 0644, which lets every other shell user on the box read the token
and impersonate the MCP server.

**Fix**: add `os.chmod(path, 0o600)` after the write, wrapped in
`try/except (OSError, NotImplementedError)`. On NTFS the call is a
no-op but is still safe; on read-only / FAT filesystems it degrades
to a warning rather than crashing.

The new test
[`test_fresh_token_is_persisted_with_0600`](tests/unit/test_mcp_token_persistence.py)
asserts the mode on POSIX; the test is skipped on Windows because
NTFS ignores the read-only bit for owned files.

## P1 still open

### P1-3  `_looks_like_refusal` raises `UNAUTHORIZED` for non-auth failures

[codex_runtime/service.py:210-219](src/littrace/codex_runtime/service.py)
raises `AppServerError(error_code=CodexErrorCode.UNAUTHORIZED, ...)`
when the codex App Server replies with one of the confusion
markers tracked by `_REFUSAL_PATTERNS`. The two failure modes that
trigger the detection — the upstream exec-mode guard and the
ChatGPT.app model-confused reply — are not auth failures. They are
transport-policy and model-layer failures respectively. Returning
`UNAUTHORIZED` makes downstream HTTP error mappers send a 401 to
the user, which sends them toward "go log in" instead of the real
fix path.

**Proposed fix (deferred)**: add a new
`MCPAppServerRefusal(AppServerError)` subclass in
[codex_runtime/errors.py](src/littrace/codex_runtime/errors.py)
with `error_code = CodexErrorCode.MCP_TOOL_REFUSED` (new enum
value), and have `_looks_like_refusal` raise that. The existing
`agent_runtime.handle_agent_chat` `except AppServerError` branch
already catches subclasses, so the fallback path keeps working.

## Lessons (added to the running list)

6. **`pragma: no cover - defensive` does not mean "skip the test"**;
   it means "the runtime exception is rare enough to skip the
   happy-path coverage". If the catch swallows a bug, no test will
   see it. The P1-1 typo survived two rounds of plugin work because
   no test fixture emits a warning. The new test
   `test_get_gateway_uses_logger_when_plugin_warning` forces the
   warning path.
7. **Long-lived secret files must be 0o600 by default**. Any
   `path.write_text(secret)` in this codebase should be paired
   with `os.chmod(path, 0o600)`. Add a helper
   `littrace.fs.write_secret(path, value)` and replace all
   ad-hoc writes with it.
8. **Test the production wiring, not just the unit**. The
   `pragma: no cover` block in `_get_gateway` looked harmless in
   isolation; it only failed when a real plugin emitted a real
   warning. The new test stubs the plugin catalog and forces the
   path so the bug surfaces in CI.
