## Lessons for next round

1. **CI workflows that swallow failures are toxic**. The
   `tests/live/test_external_services.py` syntax bug survived
   14 commits because `.github/workflows/live-e2e.yml` ran
   `pytest ... || echo warning` instead of `set -e`. A future
   round should rewrite that workflow to fail loud.
2. **Plugins need wire-surface tests**, not just
   registry-merge tests. R13 commit 3 only checked
   `enabled_tools` carried the plugin name. The spec merge
   into `mcp_servers` config was never tested; the
   round 7 CR pass caught that the plugin surface was
   effectively invisible until then.
3. **FastAPI exception handlers are not free**. A 9-class
   typed error hierarchy is worthless to the HTTP client if
   the framework returns 500 with the exception message.
   R4's `CodexErrorCode` enum needed a parallel HTTP status
   map. The R7 handler in `api/app.py` is the missing
   bridge.
4. **Hardcoded `recall_at_10` is a foot-gun**. Anyone running
   the benchmark with `--top-k 5` was reading `recall_at_10`
   in the report and assuming it meant something else. The
   dataclass field rename fixes the immediate confusion and
   also keeps the dataclass ordering legal (no required
   fields after defaulted ones).

## What's deliberately NOT done

- `gateway.py` (1467 lines) and `state_db.py` (1791 lines)
  are still large. Round 7 only extracted `state_db_schema`
  from `state_db.py`; a full split into `state_db/{session,
  binding, tool_calls, chat, async_tasks}.py` is a
  half-day refactor with no functional benefit for a
  single-operator deployment.
- The CLI (`cli.py`, 1428 lines) still uses manual
  if/elif dispatch for subcommands rather than `argparse`
  subparsers. A future round (likely when adding the 8th
  subcommand) should make that switch.
- 11 callers still import from `littrace.skill_runner`
  (the deprecation shim). They will be migrated one
  subcommand at a time as the surface area around each
  skill is touched.
